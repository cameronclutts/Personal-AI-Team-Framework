## Quick start

1. `/coordinate` — load the default role. From here on, the coordinator dispatches design,
   build, test, and review to subagents.
2. Say what you want. A clear request ("I want…", "fix…") is drafted as a work item at
   once; "let's look at…" starts a conversation first.
3. Answer one question: promote and start it. The coordinator claims it on its own branch
   in `.worktrees/<id>-<slug>`. (`/team-next` and `/team-promote` do the same by hand;
   `/run-what` shows the queue without changing anything.)
4. The coordinator runs design, `/team-work` (implementer), testers, and `/team-review`
   (adversarial reviewer), and reports after each phase. It asks you to approve the route
   only when there is design work or a live system involved. Questions from any role come
   to you.
5. When the item reaches `in-review`: {{review_step}}
6. Rule it done. `/close-work` merges and moves the item to `work/closed/`.

Several coordinator sessions can run at once, each with its own claim.

After changing how the team works, `/process-run` takes a throwaway item from draft to
done in a sandbox clone and reports where the time and tokens went, against the last run.
